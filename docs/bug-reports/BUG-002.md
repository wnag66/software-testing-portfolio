# BUG-002 Expiry Boundary Accepted

## Summary

An order submitted exactly at its expiry timestamp is accepted because the comparison uses strict `isBefore`.

## Severity

Critical

## Steps to Reproduce

1. Use order O1001 with expiry `2099-12-31T15:59:59Z`.
2. Send `validatedAt` with the same timestamp.
3. Observe the validation result.

## Expected

The boundary is expired and `accepted` is false.

## Actual

The API returns `accepted: true`.

## Root Cause

The code only rejected timestamps strictly after expiry instead of rejecting equal and later timestamps.

## Fix

Use `!validatedAt.isBefore(expiresAt)` when evaluating validity.

## Regression

`TC-API-009 / expiryBoundaryIsTreatedAsExpired` passes on `v1.0-fixed`.
